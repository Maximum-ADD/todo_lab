While you go do that — I think I found it without needing the number, actually. It fits your symptom exactly: kanban wider than list, only board view affected.

CSS Grid columns default to min-width: auto, which means a grid track won't shrink below the intrinsic width of its content — so if any card's text can't wrap (a long topic name, an unbroken monospace due-date string, etc.), that column refuses to shrink to fit grid-cols-3, forces the whole grid wider than max-w-6xl, and the page grows a horizontal scrollbar. <main>'s box itself gets pushed wider by its overflowing child, and since it's mx-auto, that shift moves its centered position — dragging the header along with it. List view has no grid, so it never has this problem.

Fix — add min-w-0 to the column so it's allowed to shrink instead of overflowing, in TaskBoard.tsx:

tsx
<div className="grid grid-cols-3 gap-4 min-w-0">
and in the Column component's root div, since flex/grid children need min-w-0 at each level to actually permit shrinking:

className={`flex-1 min-w-0 rounded-lg p-3 border-t-[3px] transition-colors ${isOver ? 'bg-gray-100' : 'bg-black/[0.015]'}`}
